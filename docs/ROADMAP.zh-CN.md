# FinancialBeancount 路线图

[简体中文](ROADMAP.zh-CN.md) | [English](ROADMAP.md)

本路线图记录不可遗漏的发布门禁。开发按可审计的小阶段推进，不代表应提前创建 Release。

## 当前交付主线

- 与账本内核一同打包的本地优先响应式 Web 应用。
- Windows、macOS、Linux 桌面控制器及可复现应用构建。
- 账本内核能够在应用内完全离线运行后，再进行 Android 原生打包。

## 发布门禁：无需卸载重装的更新

首次公开 Release 前必须完成并验证：用户账本及配置跨升级保留；迁移前备份及前向数据库迁移；版本化签名产物；用户主动检查、下载和安装；按系统与架构严格匹配；安装前展示版本、说明、大小及发布身份；下载后验证摘要和平台签名；使用原位安装或独立更新助手；网络失败不影响离线记账；失败时回滚二进制但不静默降级数据库；覆盖所有受支持历史版本；记录完全离线设备的手动更新方法。

## 已实现基础

- 用户主动触发的 GitHub Release 更新检查，以及可禁用或替换的 HTTPS 更新源。
- 平台/架构 ZIP、SHA-256 清单和 Ed25519 签名；内置公钥拒绝缺失、损坏或身份不匹配的更新。
- 有大小限制的流式下载、安全解压、路径穿越/符号链接/解压炸弹防护。
- 独立更新助手、健康检查、二进制备份和失败回滚。
- Schema 8、9 到当前 Schema 的事务迁移、校验备份、恢复入口和跨平台升级矩阵。
- 本地隐私门禁、禁止 API 缓存的浏览器边界，以及统一原始/标准交易 Schema 和可扩展账单适配器。
- 跨平台原生签名证据契约：固定发布者或指纹，并绑定准确安装包摘要。
- Windows MSI 的按用户安装、原位升级、卸载保留账本验收，以及 Authenticode、RFC 3161 时间戳和严格发布门禁。
- macOS 只读 DMG、拖放安装、替换升级数据保留，以及 Developer ID、强化运行时、公证、装订、Gatekeeper 和严格发布门禁代码。

## 后续发布批次

- 配置实际 Windows 和 Apple 发布者凭据，并在干净 Runner 上完成正向验证。
- 选择 Linux 原生包格式，完成签名、安装、升级、卸载及门禁。
- 每次正式发布后，将该版本加入持续升级兼容矩阵。
- 核心离线运行条件满足后再进入 Android APK/应用商店交付。
